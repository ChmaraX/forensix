# classifier-bench — ChmaraX/forensix#137

Candidate-agnostic bench for the URL/title classifier options shortlisted in
[#136](https://github.com/ChmaraX/forensix/issues/136), measured against a
208-row labelled fixture built from real Chrome history.

> **No winner is declared here.** `results/leaderboard.md` is a results table.
> The decision belongs to [#126](https://github.com/ChmaraX/forensix/issues/126).
> Full write-up: [`research/137-harness.md`](../../research/137-harness.md).

## Layout

| Path | What it is |
|---|---|
| `taxonomy.json` | 20 core labels, frozen from `research/137-taxonomy-proposal.md` §3 |
| `fixture/fixture_raw.json` | 208 deduplicated `(title, url)` rows with provenance |
| `fixture/fixture_labelled.json` | the same rows with gold labels — **generated**, never hand-edited |
| `fixture/LABELLING-GUIDE.md` | labeller of record, boundary rules, known gaps |
| `scripts/label_fixture.py` | the only writer of `fixture_labelled.json` |
| `harness/` | Docker image, candidates, scorer, comparators, unit tests |
| `results/` | **every file is generated**; see "Artifacts" below |

## Reproduce (one command)

```bash
cd tools/classifier-bench
./scripts/reproduce.sh
```

That builds the pinned image, runs Phase A (network on, fetch + verify
artifacts), runs Phase B three times in three separate processes with
`--network none`, runs the unit tests inside the image, then collects and
regenerates `results/`. Native arm64 wall clock: roughly 20 minutes, dominated
by the NLI cross-encoder (~4 minutes per run).

Cross-architecture:

```bash
PLATFORM=linux/amd64 ARCH_TAG=amd64 ARTIFACTS_VOLUME=bench-artifacts-amd64-v2 \
  ./scripts/reproduce.sh
```

Under Docker binary emulation on an arm64 host the NLI candidate did not
finish inside a two-hour bound, so that configuration is reported as **not
measured** rather than estimated. See `research/137-harness.md` §7.

## Collect only (a run already exists in its volumes)

```bash
./scripts/collect_results.sh [resultsVolume] [artifactsVolumeArchA] [artifactsVolumeArchB]
```

Copies the run outputs out of the Docker volumes and regenerates
`determinism-summary.json`, `cross-arch-comparison.json`, `artifact-parity.json`
and `leaderboard.md` from them. Model binaries and the compiled UT1 table are
never copied into the repo — only their Phase A manifests, which carry the
SHA-256 of every fetched file.

## Unit tests

```bash
cd harness && npm ci && npm test
```

`harness/test/` covers the scorer, the fixture validation rules, the
contamination guard, and the schema of every generated artifact — including the
rule that an unmeasured comparison must carry no verdict at all.

## Artifacts in `results/`

| File | Generated by |
|---|---|
| `results.json` | `harness/run_bench.js`, scoring layer refreshed by `harness/rescore.js` |
| `predictions/<candidate>.<arch>.main.json` | `harness/run_bench.js` — row-level predictions for error analysis, re-scoring and the cross-arch audit |
| `determinism-summary.json` | `harness/compare_runs.js determinism` |
| `cross-arch-comparison.json` | `harness/compare_runs.js cross-arch` |
| `artifact-parity.json` | `harness/compare_runs.js artifacts` (Phase A digests only) |
| `phase-a-manifest.<arch>.json` | copied verbatim from the Phase A volume |
| `leaderboard.md` | `harness/make_leaderboard.js` |

### What is deliberately not committed

The repeat determinism runs (`det1`, `det2`) produce row-level files that are
byte-identical to the `main` run apart from their `run_tag`. Committing them adds
~4 MB of duplication and no evidence, so they are gitignored. **Their decision and
raw-score digests are retained in `determinism-summary.json`**, which is what the
separate-process claim actually rests on, and `compare_runs.js determinism` refuses
to regenerate that file into a weaker verdict when the runs are absent — so the
evidence cannot be silently lost. Row-level predictions for the `main` run on every
architecture are committed.

### Re-scoring without re-running inference

```bash
node harness/rescore.js results            # recompute the scoring layer
node harness/rescore.js results --verify   # assert it reproduces the committed numbers
```

A fixture change that touches a scoring input (for example `etld1`, which is the
bootstrap cluster unit) changes published metrics without changing any prediction.
`rescore.js` recomputes exactly those fixture-dependent metrics from the committed
row-level predictions and **copies every measured quantity verbatim** — throughput,
footprint, determinism hashes, environment, artifact verification. `results.json`
`_generator.rescored_by` records `inference_rerun: false` plus the exact field split,
and `--verify` fails if recomputation drifts from the committed numbers.

Hand-editing any of them invalidates the run: `results.json` carries
`_generator.hand_edited: false` and the digests of every input that produced it,
and `harness/test/artifacts.test.js` asserts the shape those generators emit.
