## Summary

`tools/classifier-bench/` is a candidate-agnostic bench: a 208-row labelled fixture built
from real Chrome history, a 20-label frozen taxonomy, a scorer that never names a
candidate, and a two-phase Docker run (network-on fetch, then `--network none` inference).

**All six options shortlisted by [#136](https://github.com/ChmaraX/forensix/issues/136)
ran, in seven configurations** (UT1 is run twice, strict and full — see §3). Zero
candidates failed. Every number below is generated by code into
`tools/classifier-bench/results/` and rendered into `results/leaderboard.md`; nothing in
that directory is hand-written.

This is the **v2** pass. It corrects the v1 run recorded in the first version of this file
and in the commit `82cea17` artifacts. The corrections are listed in §8 — they include a
wrong persona count, a candidate that was contaminated by construction, and a leaderboard
that rendered an unmeasured cross-architecture result as a tick.

## 1. Taxonomy

`tools/classifier-bench/taxonomy.json` — 20 core labels (fixed, multi-label,
`unclassified` mandatory) plus 5 opt-in overlay labels **declared out of scope for this
bench**: no candidate emits them and the fixture carries no overlay gold rows, so scoring
them would be theatre. Sourced from `research/137-taxonomy-proposal.md` §3, which surveyed
ten external category systems (UT1, FortiGuard, Talos, Cloudflare, IAB, Chrome's Topics
API, Curlie, WebOrganizer, Magnet AXIOM, Autopsy) before the taxonomy was frozen.

Each label carries a `name`, a forensic `question`, and a `boundary` rule. Those three
strings are the **only supervision** the embedding candidates receive, and they were frozen
before labelling.

## 2. Ground truth — provenance, and what it cannot support

208 distinct `(title, url)` rows, deduplicated from 709 raw rows, from three source
packages belonging to **two staged personas** in the Magnet Forensics CTF corpus
(`digitalcorpora.org`). Full provenance and SHA-256 pins:
`research/_raw/137-chromebook-recon.md`, `research/_raw/137-takeout-recon.md`. Labelling
method, boundary rules and per-row fields: `tools/classifier-bench/fixture/LABELLING-GUIDE.md`.

| Source | Persona | Stratum | Rows |
|---|---|---|---|
| Magnet 2021 CTF Chromebook, `History` SQLite (`visits ⟶ urls`) | `eli-flatt` | primary | 130 |
| Magnet 2021 CTF Takeout, `BrowserHistory.json` | `eli-flatt` | primary | 48 |
| Magnet 2022 CTF Takeout, `BrowserHistory.json` | `rafael-shell` | niche-skewed | 30 |

**Known limitations, all of them reported inside the generated artifacts rather than only
here** (`results.json` → `fixture.census` and `fixture.limitations`):

- **208 rows, not the 500+ the issue asked for.** 65 rows are multi-label and per-label
  support is thin: only **7 of the 20 core labels clear the declared power floor**
  (≥10 gold rows AND ≥3 distinct registrable domains), 9 more carry gold rows but are
  underpowered, and 4 have no gold rows at all.
- **Two personas, not three.** The 2021 Chromebook and 2021 Takeout packages are the same
  staged persona (`research/_raw/137-chromebook-recon.md:400`). v1 said three. Corrected,
  and asserted by a test so it cannot regress.
- **43 registrable-domain clusters for 208 rows** (39 web eTLD+1 plus 4 browser-internal
  surfaces, which have no registrable domain and are keyed by scheme); `google.com` alone is
  **58.2%** of rows and the top 12 clusters are **83.2%**. Every confidence interval in this
  bench is therefore a **bootstrap clustered by registrable domain**, and
  leave-one-domain-out / leave-one-persona-out ranges are published per candidate. A
  row-level CI here would be badly overconfident.
  > **Corrected after review.** The labeller's eTLD+1 helper guarded browser-internal URLs
  > with `host.startswith("chrome")`, which also matched the real host `chrome.google.com`
  > (21 rows) and returned it as its own registrable domain — understating concentration as
  > 48.1% and resampling those rows as an independent bootstrap cluster. `etld1` is the
  > bootstrap cluster unit, the power-floor support unit and the leave-one-out group key, so
  > this moved published intervals (e.g. NLI 0.153–0.355 → 0.159–0.321). Browser-internal
  > URLs have an empty netloc, so the **scheme** is now the discriminator. A regression test
  > pins both halves.
- **24 rows share a URL** with another row (title mutations of one visit). Flagged
  (`url_group_shared`), not counted as independent evidence.
- **4 of 20 labels have zero gold rows**: `gambling`, `adult_sexual_content`,
  `cryptocurrency_exchanges`, `employment_job_seeking`.
- **Adult recall is UNMEASURABLE.** Adult false *positives* are measured against 208
  gold-negative rows (and reported with a rule-of-three upper bound when zero are seen);
  Adult false *negatives* cannot be estimated at all and are emitted as `null` with
  `measurable: false`, never as 0. A test asserts they are never rendered as 0.
- **Zero non-English rows**; **no held-out split** is defensible at 43 domains, so any
  threshold read off the coverage/accuracy sweep is selected and reported on the same rows.
- **Labeller of record is Fable (a model), not a human** — an owner-approved deviation.
  Mitigation is structural: all seven configurations are zero-exemplar (§3), so the
  contamination mechanism the issue warns about (test-set author = exemplar author) has no
  channel. The contamination guard is real code that fails the run closed, not an
  assumption.

## 3. Candidates — six shortlisted options, seven configurations

The distinction matters and the artifacts enforce it: `results.json` carries
`shortlisted_options.expected` (six) and each candidate record carries
`shortlisted_option` plus `configuration`. **Configurations of one option are not separate
options and must not be counted as such.**

| # | Shortlisted option (#136) | Family | Configurations | Supervision |
|---|---|---|---|---|
| 1 | `ut1` | 5 deterministic domain list | **2** — `strict-overlap-removed`, `full-external-list` | external list (UT1 rolling snapshot, downloaded 2026-08-08; no upstream version — pinned by compiled digest) |
| 2 | `potion-base-2M` | 3b static embedding + label-name similarity | 1 | label names only |
| 3 | `potion-base-8M` | 3b static embedding + label-name similarity | 1 | label names only |
| 4 | `bge-micro-v2` | 3 contextual embedding + label-name similarity | 1 | label names only |
| 5 | `all-MiniLM-L6-v2` | 3 contextual embedding + label-name similarity | 1 | label names only |
| 6 | `nli-deberta-v3-xsmall` | 2 entailment cross-encoder | 1 | one frozen hypothesis template |

**Why UT1 runs twice.** UT1 is a real third-party list, so unlike v1's hand-curated
`domain-list-v1` it is not authored by the fixture's labeller. But a published list still
overlaps the fixture's domains by coincidence, and that overlap is not evidence about
unseen domains. So:

- `strict-overlap-removed` — every fixture registrable domain (63,487 host entries) is
  deleted from the compiled table **before** measurement. Post-removal fixture hits: 0.
  This is a hard lower bound: coverage 0.0% on this fixture by construction.
- `full-external-list` — the published table as-is, 4,781,521 hosts across 43 mapped
  categories. 43 of 208 rows match.

Neither number may be quoted as the other, and **neither bounds production coverage**: the
strict figure is zero by construction, and nothing measured here bounds the full list from
above. Production coverage is not measurable on a 43-domain fixture.

**The UT1 snapshot is not version-pinned upstream, and cannot be.** UT1 publishes a rolling
snapshot at a stable URL with no release identifier, and `MD5SUM.LST` is regenerated
alongside the archives, so verifying against it proves transport integrity but not that the
table is the one this run measured. Identity therefore comes from the **compiled digest**,
pinned in `harness/expected_artifacts.json`
(`25058703f9ff…`, 4,781,521 hosts). `download.js` fails on drift unless `UT1_REPIN=1` is set
deliberately, and refuses any requested category archive that has no upstream MD5 entry
rather than compiling unverified data into the table. The date recorded in the manifest is
named `downloaded_on`, not a snapshot version.

## 4. Harness design

`tools/classifier-bench/harness/` — see `tools/classifier-bench/README.md` for the file map.

- **One adapter contract**: a candidate exposes
  `{ id, family, inputMode, supervision, decision, sweep, predictRaw }` and returns raw
  per-label scores. The harness supplies the fixture, applies every threshold, and scores.
  Adding a candidate never touches the scorer. (In v1 the scorer held two hardcoded,
  copy-pasted candidate blocks — that is the thing "candidate-agnostic" was supposed to
  prevent.)
- **Frozen candidate view**: candidates receive `{ row_id, title, url }`, deep-frozen.
  Gold labels, rationales, the `ambiguous` flag and the labeller identity are not
  reachable from a candidate. A test asserts the projection and the freeze.
- **One input normalisation for everyone**: `title.trim() + " " + url.trim()`, byte
  identical across candidates (`titleOnlyInput` exists for a title-only candidate; none
  used it here).
- **One coverage definition for everyone**: fraction of rows where the candidate did not
  abstain, with an `abstain_breakdown` by reason.
- **Three macro-F1 policies, all published and all rendered**, because F1 is undefined for a
  label with no gold rows and no predictions and no single number serves every purpose:
  `macro_f1_fixed_core` (all 20 — the taxonomy's frozen policy, and the leaderboard sort
  key), `macro_f1_evaluable` (labels with ≥1 gold row OR ≥1 prediction; it charges false
  positives on zero-gold labels, but its **denominator varies per candidate**, 16–20 here,
  so it structurally rewards abstention and is not like-for-like), and
  `macro_f1_powered_only` (the 7 labels clearing the declared power floor — the only macro
  computed over an identical label set for every candidate). Every per-label entry carries
  an explicit `state`, so nothing is silently scored 0 for being untestable.
  **The policies reverse the ordering** — see §6 — which is the clearest evidence that no
  ranking here is stable.
- **Operating points are hand-chosen and NOT calibrated.** Each candidate carries a fixed
  decision rule (`absoluteThreshold`, `marginThreshold`, `multiLabelDelta`) rendered per
  candidate in the leaderboard. The multi-label emission band is a **fixed, unswept**
  hyperparameter in units that differ by score axis: 0.02 cosine for the embedding tier,
  0.05 entailment-probability for NLI, 0 for the list tier. It sets how many labels each row
  emits, so macro-F1, micro-F1, exact-set match, the Adult/Health false-positive counts and
  the cross-architecture label-set differences are all functions of it. The sweep varies
  only the threshold axis and holds the band constant, so these are not tuned operating
  points and must not be read as such.
- **Charitable re-scoring** of the 16 ambiguous rows, recorded in `results.json` alongside
  the strict score, never instead of it. On a hit it credits **only the labels inside the
  labeller's own defensible set** for that row; predictions outside it stay false positives.
  An earlier version substituted the candidate's entire predicted set, which manufactured
  gold-positive rows for `adult_sexual_content` — on a fixture whose central claim is that
  Adult has none. A regression test now asserts a zero-gold label can never gain a gold
  positive.
- **Contamination guard** (`lib/contamination.js`), run **before** any measurement, fails
  closed on any declared exemplar whose URL or eTLD+1 appears in the fixture. All seven
  configurations declare zero exemplars, so it is a no-op here by construction — it exists
  so a future exemplar-supervised candidate is covered without harness changes.
- **Artifact hash verification**: Phase B recomputes SHA-256 of the **six pinned large
  artifacts** (five ONNX graphs plus the DeBERTa `spm.model`) against
  `expected_artifacts.json` and throws on **mismatch or absence** before running anything.
  All 40 Phase A files are revision-pinned at their URL and digest-recorded in the Phase A
  manifest; the 34 small tokenizer/config blobs are not additionally pinned here because
  their upstream git blob oids are not SHA-256 values.
- **Network isolation is asserted, not trusted**: Phase B attempts an outbound request and
  records the result. `network_isolated: true` in `results.json` means the request failed.
- **Leaderboard is generated** (`make_leaderboard.js`) from `results.json`. Unmeasured
  cells render as "not measured".

## 5. Determinism — same process, separate processes, then architectures

Three distinct questions, three distinct answers.

**Same process.** Each candidate is run twice inside one process and the decision digests
compared. All 7 configurations: match.

**Separate processes.** An in-process repeat cannot detect fresh-process nondeterminism
(ONNX Runtime arena state, thread pools, memory layout). Phase B was therefore run **three
times in three separate containers** (`main`, `det1`, `det2`) on native arm64, and the
per-row prediction files compared by `compare_runs.js`:

> **All 7 configurations: 3 runs, identical decision digests AND identical
> full-precision raw-score digests.** `results/determinism-summary.json`.

Those three arm64 processes are the whole of the separate-process evidence. No fourth
arm64 process was run. The only other process in this ticket is the emulated x64 run, which
answers a different question and does **not** corroborate this one — it reports differing
raw-score digests for four of six comparable configurations and differing decisions for two
(§7).

The row-level artifacts for `det1` and `det2` are not committed: they came out
byte-identical to the `main` run apart from their `run_tag`, so committing them would add
~4 MB of duplication to a repository whose entire packed history is smaller than that. What
carries the claim is their decision and raw-score **digests**, retained in
`results/determinism-summary.json`. `compare_runs.js determinism` refuses to regenerate that
summary into a weaker verdict when the row-level runs are absent, so dropping the duplicates
cannot silently erase the measurement. Row-level predictions for the `main` run on every
architecture **are** committed, because they are the substrate for re-scoring and for the
cross-architecture audit.

**Across architectures — bounded, and partly unmeasured.** See §7.

## 7. Cross-architecture: what was measured, and the amd64 bound

**Phase A inputs are identical across architectures — verified.**
`results/artifact-parity.json`, generated from the two Phase A manifests:

- **40/40 model artifact files byte-identical by SHA-256** between `arm64` and `x64`.
- **Compiled UT1 host→label table digest identical**:
  `25058703f9fff7f05cb161c1fa7d7f16db2f5f3a3f755448c5a1aa908279bce3`, 4,781,521 hosts,
  0 of 43 category digest mismatches.

That is parity of *inputs* only. It says nothing about inference output, which is measured
separately.

**The amd64 Phase B run is bounded and incomplete.** `linux/amd64` was run under Docker
binary emulation on an arm64 host — no native amd64 hardware was available. The emulated
Phase B run was **stopped after more than two hours, during the NLI cross-encoder**, which
is the seventh and by far the slowest configuration (≈4 minutes natively). Six of seven
configurations had already written complete 208-row prediction artifacts; NLI wrote none.

Because the emulated run never reached the end, **no `results.x64.json` was written**, so
there is no persisted amd64 environment record (Node/ORT version, the network-isolation
assertion, image digest). The comparison below rests on the six complete per-candidate
prediction artifacts and on the amd64 Phase A manifest, which are self-verifying (each
prediction file carries its own decision and raw-score digests over 208 rows), but the
amd64 side is deliberately **not** described as a fully recorded run.

### Finding: cross-architecture determinism does not hold for the int8 contextual encoders

The v1 spike (`tools/classifier-bench/spike/SPIKE-REPORT.md` §6) found bitwise-identical
potion-2M embeddings for **one fixed test string** and generalised architecturally. v1 of
this harness found 28/208 potion-2M row embeddings differing, with no decision impact.
v2, over the full 208-row distribution and five model-backed configurations, refines that:

- **The deterministic list tier is bitwise identical**, decisions and scores, both
  configurations. No surprise: it is a hash lookup.
- **Static-embedding candidates (potion 2M/8M) diverge in raw scores but not in
  decisions** on this fixture. The float difference never crossed a top-1 or margin
  boundary here. That is an observation on 208 rows, not a guarantee at 100k-row scale.
- **int8-quantised contextual encoders diverge at the decision level.**
  `all-MiniLM-L6-v2` (`model_qint8_arm64.onnx`) emits **different label SETS on 53 of 208
  rows** — 25.5% of the fixture. A further 12 rows carry the same labels in a different
  rank order, which is not a decision difference: `predicted` is emitted in descending-score
  order, so an order-sensitive comparison inflates the figure to 65. Set and order are now
  counted separately (`differing_label_sets` vs `differing_label_order_only`).
  `bge-micro-v2` (`model_quantized.onnx`) differs on 1 set. Examples are in
  `cross-arch-comparison.json` → `differing_examples`.
- **Most of that divergence is threshold sensitivity, not a changed model opinion.** Of
  MiniLM's 53 set differences, **41 occur with an unchanged raw top-1**: the fixed, unswept
  multi-label emission band (`multiLabelDelta = 0.02` cosine) admitted or dropped a
  borderline label. Only **24 rows** change the model's own first choice. A wider or
  narrower band would move the headline number, so this figure measures the operating point
  as much as the architecture.
- **NLI is unmeasured**, and must not be assumed either way from its neighbours.

**Caveat that limits how far this travels:** amd64 ran under emulation, not on native
amd64 silicon. A divergence observed here is between native arm64 and emulated x64. It is
enough to refute "bitwise identical by construction" as a design assumption for the int8
encoder tier, and it is not enough to quantify what two native hosts would do. The
`emulation_note` field records this next to the numbers.

Practical reading for #126: if reproducible output across a user's machines is a
requirement, the list tier and (on this evidence) the static-embedding tier are the only
options that currently support it, and the int8 contextual tier would need either a
native-hardware cross-check or a documented tolerance.

## 9. Deviations from the issue's requirements — logged, not hidden

| Requirement | What happened | Why |

### 10a. Why the scoring layer was recomputed, and why that is not a shortcut

Two audit fixes changed published numbers without being able to change what any model
predicted: the `etld1` registrable-domain bug (§2) and the charitable-scoring fix (§4).
Every emitted decision was already persisted per row, and thresholds, model artifacts and
gold labels were untouched, so re-running the container would reproduce the same predictions
and cost ~20 minutes on arm64 plus a multi-hour emulated amd64 leg.

`harness/rescore.js` therefore recomputes the **scoring layer only** from
`results/predictions/*.arm64.main.json`, and is explicit in `results.json` about the split:

- **Recomputed** (pure functions of fixture × predictions): `per_class`, all three macro
  policies, `micro_f1`, `label_states`, multi-label row metrics, `coverage`,
  special-category confusion, confusion pairs, the coverage/accuracy sweep, bootstrap CIs,
  leave-one-out sensitivity, the leakage diagnostic, charitable scoring, and the fixture
  census.
- **Copied verbatim, never re-derived** (measurements of the machine, not the fixture):
  `throughput`, `disk_footprint`, `determinism` hashes, `environment`,
  `inputs.artifact_verification`, and the Phase A manifest.

Fidelity is asserted rather than assumed. `node harness/rescore.js <dir> --verify` fails if
recomputation does not reproduce the committed numbers exactly; run against the pre-fix
fixture it reproduces all seven candidates to <1e-12, and `harness/test/rescore.test.js`
pins reconstruction fidelity and idempotence. `results.json._generator.rescored_by` records
`inference_rerun: false` and the exact field split, so no reader can mistake a recomputed
number for a re-measured one.

### 10b. Reduced-category follow-up

After the 20-label run, the owner requested a small follow-up: merge the taxonomy into six
broad displayed categories plus `unclassified`, and run only Potion 8M and BGE Micro. The
original fixture remains unchanged. `scripts/make_reduced_fixture.js` deterministically maps
its labels into `fixture/fixture_reduced.json`; rows with no in-scope source label map to
`unclassified / outside reduced scope`.

The follow-up used the original candidate operating points. It did not calibrate a threshold
on the fixture. For these label-similarity models, the reduced label name, question and
boundary text are the complete supervision. That text was authored after the first results,
which is the strongest reason this run is exploratory rather than independent confirmation.

Phase A downloaded only the two required pinned models. Phase B ran three separate arm64
processes with `--network none`; both candidates matched at the decision and raw-score levels
across all three processes. This follow-up is arm64-only and adds no cross-architecture result.
The original §7 run found one BGE label-set difference on amd64. Full evidence is in
`results/reduced/`.

| Candidate | 7-label macro-F1 | Micro-F1 | Coverage | Domain-cluster 95% CI |
|---|---:|---:|---:|---:|
| BGE Micro | **0.440** | 0.462 | 74.0% | 0.374–0.542 |
| Potion 8M | **0.395** | 0.485 | 98.6% | 0.237–0.436 |

The reduced score is higher than each model's 20-label point estimate, but the values are not
directly comparable because the target changed. The reduction did not reach the owner's
provisional 0.6 macro-F1 gate. The two intervals overlap, `unclassified` F1 is 0.188 for BGE
and 0 for Potion, and several displayed categories remain below 0.5 F1. Fewer categories
helped, but did not turn either zero-shot label-similarity model into a reliable classifier.

This run is post-hoc by construction: the reduced taxonomy was selected after reading the
first results. It is useful product evidence, but not an independent confirmation result.
Coverage also counts `unclassified` as abstention, including a correct catch-all prediction,
so the 74.0% and 98.6% values must be read with each model's `unclassified` F1. The reduced
fixture retains the `search_query` identifier for the wider Search, Reference & Education
label so the shared in-site-search validation rule remains applicable.

## 11. What #126 still needs before it can decide

- **Ground truth for `adult_sexual_content`** — genuinely unmeasured, not merely low. A
  targeted top-up for this label is worth more than growing the fixture toward 500 rows
  generically.
- **A fixture with more than 43 domains.** Every interval here is domain-clustered and
  wide because of that, and the field is not statistically separated.
- **Cross-architecture behaviour of the NLI configuration**, and a native-amd64 (not
  emulated) check for the int8 contextual encoders, before any of them is treated as
  reproducible across a user's machines.
- **Non-English coverage.**
- **An exemplar-supervised variant** (e.g. Curlie-sourced) of the embedding tier — the
  zero-shot numbers here are a lower bound on family 3, not a ceiling. Note that such a
  candidate would be the first to actually exercise the contamination guard, and would need
  a labeller who did not write this fixture.
